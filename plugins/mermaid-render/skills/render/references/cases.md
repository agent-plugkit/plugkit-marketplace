# 少量 Good / Bad Cases

这些案例只校准判断，不是可复制模板。

## 风格不是换肤

**Good：** 同一个三阶段流程在现代 Swiss Style 中使用钴蓝、超轻标题、微型索引和模块网格；在 JAPANESE MA 中保留同样清楚的节点网格，再用留白、细线和一处朱色建立节奏。两者都能快速扫读，但视觉逻辑不同。

**Bad：** 三套风格共用完全相同的卡片、尺寸和坐标，只替换颜色、字体和阴影。

## 自由不能损伤语义

**Good：** 为关键节点增加图标或场景，把次要节点降为简洁文字标记，同时保留全部 label、边、箭头方向与分组。

**Bad：** 为了“更好看”合并两个节点、改写业务术语、删除回边，或加入 Mermaid 中不存在的新步骤。

## 留白与装饰都要工作

**Good：** 每个节点拥有独立、不重叠的网格区域；留白清楚分隔阶段并为回边预留线槽，一块钴蓝或朱色只强调真正的转折点。

**Bad：** 标题压住节点、徽标盖住 label、节点互相叠放，或借“留白”把节点散落到难以追踪；空白和装饰都没有帮助读者判断从哪里开始、往哪里走。

## 选择合适的方式

**Good：** 高密度架构图用 HTML 保证文字和连接可编辑；低密度概念流程用 Imagent 主动为节点配图并建立叙事场景。

**Bad：** 因为已有 HTML 模板就强迫所有 Imagent 任务先走 HTML，或因为图片更吸睛就把几十个精确节点交给生成模型碰运气。
