# 使用 style.md

`style.md` 是 musepool 为一次制作解析出的风格：一个 Template 按当前场景展开后的全部约定。Workflow 只读这一份，不直接读风格库。

## 获取

Brief 写完后调用 `musepool`，带上场景（`graphic`、`web`、`slides`、`diagram`、`data`）、内容气质和硬约束。用户点名了风格，或给了品牌规范、既有设计系统、参考图时，一并交给 musepool：它会把用户的规范整理成 `source: user` 的 Template，再解析成同样的 `style.md`。

`style.md` 放在作品目录里。系列作品和同一篇文章的多张配图共用一个 Template 和变体；场景不同的作品（例如插图和数据图）各按自己的场景解析一份。

## 各部分怎么用

- **frontmatter 的 `tokens` 与 Tokens 段的 CSS**：所有颜色、字体、字号、行距、间距、圆角、线宽和栏宽都从这里取。网页直接接入 `:root` 变量和其后的 `@media` 断点块，项目已有 token 体系时映射过去；SVG、画布或其他工具把对应的值填进参数。
- **展示字号**：本场景适配要求标题跨满某几栏（或竖排到某个长度）时，用 `muse.py fit` 按字数、字距、内边距和边框推导（字距默认取风格的中文展示字距；竖排直接给出一半和三分之二两档），结果可以超过 `size-display`；网页使用它给出的流式表达式，标题设为不换行。适配没有这样要求时，直接用 `size-display`。
- **Seed 要点与适用与边界**：要点是做法，适用与边界是限制，两者同样要遵守。
- **制作工具**：Seed 下写着「制作工具」时，插件已经提供了实现这条做法的工具。从插件根目录按路径把它复制进作品目录，参数从 tokens 里取，用法写在工具文件的开头，不要再手写一套。
- **数据色板**：只在场景 `data` 出现。frontmatter 的 `data` 给分类、顺序、发散三组颜色，CSS 里对应 `--data-cat-*`、`--data-seq-*`、`--data-div-*`；用法写在「数据色板」一节。
- **文字配对**：文字颜色和背景只按这张表组合；标着「仅大字」的组合不放按钮、标签或正文。
- **字体**：网页加载列出的 CSS 地址；导出图片前等字体加载完成。加载失败时记下实际使用的回退字体，写进交付说明。
- **文法**：用来排你从结构原型里选出的结构。它决定区域占几栏、对齐在哪条轴、层级靠什么建立、留白落在哪里。
- **本场景适配**：这个风格在当前媒介的具体做法，优先于通用文法，也优先于 Seed 要点与适用边界里和它冲突的条目。写着「未验证适配」时，由你按文法推导，交付时列出推导了哪些决定。
- **机检**：只在部分风格的 graphic、web 和 slides 场景出现。按角色说明给元素加 `data-mk`，检查脚本会量出这些规则的数值并写进摘要；它量过的规则不用再自己写代码量。没有列进机检的规则，仍然靠目视或自己量。
- **常见误用**：评审时逐条对照。
- **范例**：每条写明借什么、不借什么；想看原始记录时用 `muse.py show <id>`。只看方法，不搬运范例的内容、文案、品牌和图片。末尾有「制作示例」时，按路径读那份示例，学它从 Brief 到评审的判断过程，不照搬构图。

## 状态

- 风格的状态以 Template 为准；它引用的 Seed 是 `draft` 只表示库内维护进度，交付时不另行说明。
- `draft`：风格尚未经过人工确认，交付时写明。
- `user`：用户自己的规范优先；与 style.md 中其他建议冲突时，以用户规范为准。
- `composed`：混搭风格，交付时说明它由哪些 Seed 组成。

需要 style.md 之外的值时，先回到 musepool 调整风格；确实只在本作品使用的值，写进交付说明。
