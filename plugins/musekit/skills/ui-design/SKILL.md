# UI Design

把用户要完成的任务组织成可用、清楚且有辨识度的界面。默认完成实现并在浏览器查看；用户只要设计方向或方案时按其范围交付。

## 从任务到界面

1. **找到主任务。** 阅读现有页面、组件和项目规则，确定用户进入页面后要看懂什么、做什么，以及操作完成后的反馈。将内容层级和关键状态写清楚后再排版。
2. **确定视觉方向。** 直接使用已确认的设计系统、参考或 seed。需要探索时请 `musepool` 提炼方向；参照[seed 简报](../../references/seed-brief.md)区分可借鉴的视觉关系和需要重新设计的界面结构。
3. **组织页面和状态。** 根据任务选择阅读型页面、集合浏览、任务工作台等结构。建立主操作、导航、内容密度和桌面/移动布局；覆盖实际涉及的加载、空、错误、选中与完成状态。
4. **实现。** 沿用项目技术栈和组件，加入必要的布局、内容与交互。颜色、字体和动效服务任务反馈，避免为了像参考而替换可用组件或引入另一套工程栈。
5. **打开并使用。** 完成一条真实任务路径，再检查窄屏、长文本、键盘和所涉及状态。根据实际画面修正层级、间距、断行与反馈。

做版面选择时读取[场景方法](references/methods.md)；需要校准一个完整流程时读取[制作示例](references/examples.md)。这些是判断方法，不是强制页面模板。

## 制作时守住的事实

- 已有品牌和组件契约优先。借用 seed 的色彩职责或字体层级，不把海报的文字遮挡、固定比例和纸张工艺直接搬到控件上。
- 中文与混排文字需要实际可用的字体和回退。字号、容器宽度与行高一起检查，不能只用英文短句调好页面。
- 主操作、焦点、禁用、错误和选中状态要能区分；颜色之外给出文字、形状或位置反馈。动效影响信息获取时提供 reduced-motion 行为。
- 图像选择应有内容目的；使用真实可用的素材或明确创作的插画。数据演示需标明示例，不能伪装成真实客户、指标或结果。

## 交付

交付可运行代码和查看入口，说明已走通的任务与所检查的状态。用户要求截图时提供实际页面截图。浏览器或运行环境不可用时交付现有代码和具体限制，不把代码检查当作视觉验证。
