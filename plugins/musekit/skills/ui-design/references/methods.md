# 界面方法：先决定怎样使用

## 内容决定结构

| 任务 | 可采用的组织方式 | 关键取舍 |
| --- | --- | --- |
| 阅读、理解一个主题 | 编辑型长页、章节导航、图文交替 | 用论述顺序安排内容；首屏让读者知道主题和下一步，不自动添加营销区块 |
| 寻找、比较、选择条目 | 列表或网格、筛选、详情预览 | 密集元数据更适合对齐的行；图像决定选择时让图像获得面积；保留筛选结果和空状态 |
| 完成连续任务 | 分步流程、主工作区与上下文栏 | 每一步的输入、反馈和恢复方式先于装饰；主操作位置稳定 |
| 监控与处理 | 汇总加工作队列、详情面板 | 先呈现待处理事项与异常，再呈现背景统计；状态不能只用色块表示 |

同一产品可能组合几种方法。先让信息关系成立，再从 seed 借取视觉节奏；不用参照的首页结构替代用户流程。

## 把灵感转成界面选择

- **大字与对比**：可用于区分页面主题和工具区；重复条目的正文仍需要稳定字号，不把所有列表项做成海报标题。
- **克制的强调色**：用于当前选择、主操作或真正重要的反馈。状态较多时用标签、图标和位置补充，避免一色多义。
- **非对称**：让主工作区与背景信息的面积反映任务重要性。窄屏按优先级重排，不能仅等比缩小。
- **动效**：让元素移动解释状态变化，例如详情展开与筛选反馈。耗时操作要有进度或结果信息，不能只做装饰循环。
- **材质与图像**：在内容需要时使用。品牌照片和手绘图可以增加辨识度，表单与数据表仍需清楚的边界和文字。

## 先有真实文字，再调布局

用用户实际语言和内容检查长标题、长数字与多行说明。字体加载后检查断行；让容器随正文增长，给可截断内容提供明确的查看方式。中文标题不依赖仅含拉丁字形的展示字体。

为关键操作定义可见反馈和恢复路径。例如筛选为空时显示当前筛选及清除入口；保存失败时保留输入。示例中没有异步请求，就不伪造成功的网络操作。

## 在浏览器验证

先执行主任务，再看目标窄屏与内容极值。确认键盘能到达操作、焦点可见、状态说明可读取，尺寸变化没有藏起关键信息。若动效承载状态转换，检查 reduced-motion 下仍可理解。

对照实际页面判断是否完成：层级是否清楚、密度是否适合工作、视觉重点是否服务任务。检查清单不能替代观看和使用。
