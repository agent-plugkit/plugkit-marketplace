# 界面制作示例

[可直接打开的观察记录界面](examples/community-observations.html)包含下例的全部数据、响应式布局与筛选逻辑。它展示一次具体取舍，不是所有 UI 的起始模板。

示例内容均为虚构教学材料。下面给出请求、输入、取舍、实现和检查，便于复现流程；无需复刻版面。

## 社区观察：记录浏览界面

**请求**：做一个本地可运行的“社区观察”记录页，支持分类筛选和文字搜索，在手机上也能用。没有服务端，不需要编辑或登录。

**内容**：标题“社区观察”，说明“沿着日常路线，记录城市的细小变化。”分类为“全部 / 街道 / 植物 / 声音”。展示以下四条示例记录：

| 标题 | 分类 | 地点 | 日期 |
| --- | --- | --- | --- |
| 台阶边的新芽 | 植物 | 东侧步道 | 2026-05-04 |
| 雨后的街角 | 街道 | 桥下路口 | 2026-05-05 |
| 清晨的自行车铃 | 声音 | 河岸 | 2026-05-06 |
| 墙边的常春藤 | 植物 | 旧书店 | 2026-05-07 |

**Seed**：共享 seed 简报中的 `mC1nkP2t`。借 Cobalt 与 Terracotta 的主次关系和疏密变化；这里是可筛选列表，不采用印刷肌理、字图遮挡或固定海报比例。

**选择**：编辑型标题区与紧凑工具区分开；条目按行对齐，方便扫描日期、分类和地点。用 Cobalt 表示当前筛选，暖色稍加深，用于小型标记与键盘焦点。手机上工具区换行，日期移动到条目下一行。

**实现**：在已有项目中复用组件；本独立示例用单个 HTML、CSS 和少量 JS 即可。使用带可访问名称的搜索框和原生按钮，筛选按钮更新 `aria-pressed`；搜索与分类共同筛选四条记录，结果数同步更新。空结果显示“没有找到匹配的观察”和清除筛选入口。

**成品检查**：初始四条；选择“植物”得到两条；输入“常春藤”得到一条；输入不匹配关键词出现空状态；清除后恢复四条。用键盘操作，再看窄屏和中文断行。

**容易做错**：把四条记录变成等高海报卡，按钮被大字遮住；只有视觉选中而没有筛选行为；宣称已连接真实数据库。

## 已有设计系统的预约表单

**请求与输入**：已有组件库和品牌色，增加预约日期、时段、联系电话和提交反馈。接口由项目提供；必填规则来自现有接口文档。

**选择**：先沿用项目表单、验证和日期组件。明确不可用时段、提交中、接口错误与完成状态；无需为了产生 seed 再做风格探索。

**制作与交付**：完成真实提交路径；错误时保留输入并定位字段，完成时显示接口确认的信息。交付代码和浏览器验证结果。

**容易做错**：从参考网站引入第二套组件或技术栈；为了“更有设计感”缩小标签或隐藏错误说明；只做静态成功画面。
