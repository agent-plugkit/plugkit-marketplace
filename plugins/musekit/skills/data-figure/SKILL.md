# Data Figure

让读者从图里读到数据支持的那个结论，并且读得准。默认交付成品图、数据和可以重新生成它的绘图代码；用户只要方案时，停在对应的步骤。全程守住[底线](../../references/critique.md#底线)。

## 范围

- 位置或长度由数值决定的图：比较、趋势、分布、关联、组成。
- 学术出版的结果图另外遵守[学术出版 profile](references/academic.md)：统计口径、出版尺寸和期刊规范都在那里。
- 关系、流程、装置和科学过程示意交给 `diagram-design`。一张图里既有数据面板又有示意面板时，在这里拼版，示意面板由 `diagram-design` 做好后作为一个面板放进来。
- 正文里只有两三个数字、没有表格或数据文件时，不新建数据图，数字留在文字里。

## Brief → 风格 → 编码 → 制作 → 评审

1. **写 Brief。** 回答五个问题：
   - 这张图回答什么问题，读者看完应该记住哪一句话。这句话必须由数据支持，不由你补充。
   - 数据是什么：文件或表格、变量、单位、样本量、缺失值，已有统计量的口径（SD、SE 还是置信区间）。
   - 在哪里被看到：文章配图（像素宽度）、报告、幻灯片，还是期刊（栏宽、格式、分辨率）。投稿或论文用图按学术出版 profile 处理。
   - 哪些文字必须逐字准确：标题、变量名、单位、数据来源与署名。
   - 怎样算成功：2–3 条可以检查的标准。

   缺数据、单位或口径不明时询问用户；用户要求直接做时，示例数据明确标为示例，不能编造的数据留空，并在交付里列出。完成标准：每个问题都有答案、写着「由我创作」，或列为待补。
2. **取风格。** Brief 写完后再取，用户点名了风格也一样。带着场景 `data`、Brief 里的气质和约束调用 `musepool`，得到作品目录里的 `style.md`，按[使用 style.md](../../references/style.md)使用。文章里已经有共用的 style.md 时，用它的 Template 和变体以场景 `data` 另解析一份。期刊或机构给了制图规范时，把它作为硬约束一起交给 musepool；字号、线宽和字体以规范为准。完成标准：`style.md` 已写出，变体已定；变体只换强调色而图里不用强调色时，写明变体不影响画面。
3. **选编码并用文法排它。** 从[编码原型](references/structures.md)中按问题选一种（多面板时每个面板各选一种），写出每个变量映射到哪个通道（位置、长度、颜色、形状、分面）。再按 style.md 的文法和本场景适配决定：结论句和图题放在哪里、轴和网格退到多弱、强调落在哪个序列、用直接标注还是图例、多个面板怎样排。颜色按[制作方法](references/methods.md#把-stylemd-接进绘图工具)的映射分配，这条映射优先于文法里为版面列出的强调色位置：区分多个身份用数据色板；只强调一项时用 `accent`，其余退成 `ink-muted`；两种做法不在一张图里混用。style.md 写着未验证适配时，文法里针对海报或网页的具体规定（展示字号、页脚版权行）不搬进图，图题和字号按映射表。完成标准：写出一份编码说明，每个变量有通道，每个序列有颜色和标注方式。
4. **制作。** 按[制作方法](references/methods.md)选工具，读取数据文件作图，不手抄数值；样式值取自 style.md。完成标准：目标尺寸的成品已导出，数据和代码能重新生成它。
5. **评审。** 按[评审循环](../../references/critique.md#评审循环)检查，本媒介的清单是：
   - 数据准确：从数据重新核对每个画出的值、汇总量和单位；轴范围、基线、变换和缺失值处理都有交代；没有数据不支持的趋势线、显著性标记和误差条。
   - 编码清楚：同一序列在各面板里颜色和形状一致；序列之间除了颜色，还能靠直接标注、形状或线型区分；颜色只取 style.md 的数据色板、`accent` 和文字色。
   - 去色后仍能分清各序列，并找到结论句指向的那一项。
   - 按目标展示尺寸（文章宽度、幻灯片或期刊栏宽）查看：刻度、标注、图例和图注都读得出。
   - 学术出版另按 profile 的清单核对。

   完成标准：按所在档位走完评审，没有实质问题。

## 交付

交付成品（PNG；学术出版加 SVG 或 PDF）、数据文件、绘图代码、`style.md`，以及一段给正文排版用的图注：变量、单位、统计口径和数据来源；图里只留一行短注（如示例数据声明）。说明编码选择、风格状态（`draft` 或未验证适配时写明推导了哪些决定），以及评审走的档位和实际检查了什么。Brief 和编码说明随交付说明一起写进作品目录。

完整的判断过程见[制作示例](references/examples.md)。
