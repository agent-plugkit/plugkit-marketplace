# Slides Design

让一份演示文稿每页只说一件事，整份按一条讲述线推进，并且在会场和导出的 PDF 里都读得清。默认交付可翻页的 HTML、PDF 和逐页 PNG；用户只要大纲或页序表时，停在第 3 步。全程守住[底线](../../references/critique.md#底线)。

## 范围

- 多页、按一条讲述线推进的作品：现场分享、汇报和讲稿配图。
- 单页作品交给 `graphic-design`；要单独交付的数据图或图解交给 `data-figure`、`diagram-design`。

## Brief → 风格 → 页序 → 制作 → 评审

1. **写 Brief。** 回答六个问题：
   - 在什么场合被谁看：现场讲（投影或屏幕共享，有人讲解），还是发出去自己读（只看 PDF）。讲多久，大约几页。画幅默认 16:9（1920 × 1080）。
   - 听众是谁，讲完要他们记住哪一句话、做什么。
   - 讲述线：开场 → 中间几段 → 收尾，每段要证明或说明什么。
   - 哪些信息必须逐字准确：标题、讲者、日期、数据与来源、引文和出处、Logo。
   - 有哪些可用素材：照片、数据文件、图表、品牌资产。
   - 怎样算成功：2–3 条可以检查的标准。

   密度按场合定：现场讲时一页一个论点，要点不超过 4 条、每条一行；自己读时每条可以两行，数据页写明来源。缺少必需事实时询问用户；用户要求直接做时，可以创作的内容标为示例，不能编造的事实（数据、引文、网址、身份）留空，并在交付里列出。数据的来源和对比基准也是事实：数据是讲者或其机构自己的记录时，来源写成「<机构名>统计」；来自外部而用户没给出处时不猜，页面上写「来源：待补」，交付时列为待补。由你创作的条目（对比页的条目、举的例子）加「示例」小标，一组并列的条目整组标一次，放在组的上方或下方；页标题、引导句这类措辞不用标。Brief 写在对话里就够了；必须逐字准确的事实另存成一行一条的 `facts.txt`，第 5 步的检查会用到。短数字带上单位或标签写（「24 场修理日」而不是「24」），否则会在别处误命中。完成标准：每个问题都有答案、写着「由我创作」，或列为待补。
2. **取风格。** Brief 写完后再取，用户点名了风格也一样：变体和约束要从 Brief 里来。带着场景 `slides`、Brief 里的气质和约束调用 `musepool`，得到作品目录里的 `style.md`，按[使用 style.md](../../references/style.md)使用。完成标准：`style.md` 已写出，变体已定。
3. **排页序，再用文法排每一页。** 先写一张页序表：每页一行，写页型和这一页要说的那一句话（页标题尽量写成断言）。页型从[页型原型](references/structures.md)里选，按讲述线安排节奏。再按 style.md 的文法和本场景适配，为每种页型定下区域的栏位、对齐轴、层级和留白；同一页型在整份里用同一套区域位置。页型原型和本场景适配说法不同时（要点编不编号、出处放在哪里），以适配为准。完成标准：页序表写完，每种页型的栏位已定。页序表写在对话里，交付说明里附上。
4. **制作。** 按[制作方法](references/methods.md)从起始模板开始，每页一个 `<section class="slide">`，接入 style.md 的变量和字体。完成标准：HTML 能在浏览器里翻完全部页。起始模板的骨架和翻页脚本没改动时，翻页已由插件的测试覆盖，不用另写脚本验证。
5. **评审。** 按[评审循环](../../references/critique.md#评审循环)检查。先跑插件的检查脚本（插件根目录是本文件往上两级；在能解析 Playwright 的目录里运行，缺少时它会打印安装命令）：

   ```bash
   node <插件根>/scripts/inspect_page.mjs deck.html --canvas 1920x1080 --slides .slide --facts facts.txt
   ```

   页面有加载后才作画的脚本（如网点模块）时，加 `--ready` 传它画完的条件。它按打印版式逐页检查：每页单独显示，查遮挡、裁切、出画布、小于 `size-meta` 的字和 style.md 之外的颜色，并报出实际渲染的字体；事实按整份计数，标出在第几页。它把逐页 PNG 导出到 HTML 旁的 `deck-slides/`，PDF 导出为 `deck.pdf` 并核对页数和页面尺寸，在 `review/` 里留下总览图（全部页面按四分之一缩小排在一张图上，彩色和灰度各一张）和 `report.json`。终端只打印摘要。style.md 有「机检」一节时，先按它给元素加 `data-mk`，摘要里会逐页列出版式规则量到的数值；某种标记只在部分页面出现时，没有它的页面不报，整份都没有才报「not measured」。本媒介的清单是：
   - 看总览图：页型的节奏和讲述线一致，密的页之间有低密度的页；同一页型的区域位置一致，页码和页眉不漂移。
   - 每页只说一件事；页标题单独读也能看懂这一页的结论。
   - 按 100% 看每一页：最小的字是 `size-meta`，只用于页码、来源这类附注；要读的内容至少是 `size-body`。
   - Brief 中必须准确的信息逐字正确，数据页写明来源。
   - 看灰度总览图，仍能凭网格、尺度和对齐认出 style.md 描述的风格。
   - PDF 的页数和页面尺寸由脚本核对。有 PDF 阅读器时打开看一遍，重点看网点、混合模式这类画布效果；没有时在交付说明里写明 PDF 没有目视。

   完成标准：按所在档位走完评审，没有实质问题。

## 交付格式

- **HTML**：一个文件，浏览器里全屏放映，用方向键、空格或点击翻页，地址里的 `#3` 打开第 3 页。
- **PDF**：每页一张，页面尺寸就是画布；由第 5 步的检查脚本按打印版式导出，文字是矢量。会场电脑不能用浏览器放映，或者会场断网（HTML 的网页字体加载不了，顶满的标题可能被裁）时，放这份 PDF。
- **PNG**：每页一张，由同一次检查导出，用于发群、插进文档或别的软件。
- **不支持**：可编辑的 .pptx、Keynote 和 Google Slides 文件。用户需要在这些软件里继续改时，如实说明：可以把 PDF 或逐页 PNG 放进去当整页图片，但文字不能再编辑。

## 交付

交付 HTML、PDF、逐页 PNG 和 `style.md`。交付说明写出 Brief 的要点、页序表、每种页型的栏位决定、关键的设计选择、风格状态（`draft` 时写明；本场景适配写着「未验证适配」时，列出推导了哪些决定），以及评审走的档位和实际检查了什么。浏览器或 Playwright 不可用时，交付 HTML 并写明没有导出 PDF、没有做视觉验证。

完整的判断过程见[制作示例](references/examples.md)。
