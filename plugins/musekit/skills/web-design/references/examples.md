# 界面制作示例

两份示例用同一条流程做同一类任务：为一个虚构的活动或刊物做单文件官网首页，没有现有项目和服务端，主任务是填一张表单。风格不同，页面的切分方式、主操作的位置和状态的形态都不同。读它们是为了学**判断过程**：怎样从 Brief 和 style.md 推出每个视口的区域与栏位，评审在浏览器里查出了什么、怎样修正。不照搬构图、文案和代码结构；换一个风格或换一项任务，结论都要重新推导。

| | [新粗野主义：《造物集市》](examples/neo-brutalism-maker-fair.md) | [编辑衬线：《长河》季刊](examples/editorial-serif-long-river.md) |
| --- | --- | --- |
| 主任务 | 报名摆摊（类别格可以预选类别） | 订阅季刊 |
| 页面原型 | 介绍与转化 + 完成任务 | 介绍与转化 + 完成任务 |
| 页面怎样切分 | 三面拼板墙，每面墙的切分方式不同，每面都有顶满的标题和压缝贴片 | 一张扉页式首屏，下面是用通栏细线隔开的居中章节 |
| 手机上怎样重排 | 板单列堆叠，仍共用横线 | 中轴不变，旁注移到正文之前，版权行按事实断行 |
| 状态的形态 | 出错时边框加粗并贴一张原因标签；完成后表单板换成主色 | 出错时底线加粗加一行强调色说明；聚焦用描边框；完成后居中的确认文字替换表单 |
| 评审改得最多的 | 首屏以下的墙不满足文法；贴片在窄屏压住可点击的格子 | 示例标注缺失、完成态措辞失实、聚焦与出错分不开 |

两件作品都没有后端：完成态如实写「信息没有发送」，不伪造提交成功；用户没给的事实（价格、网址、联系方式）写「待公布」。

## 项目已有设计系统时

上面两份示例都是从零开始。项目已有组件库和品牌规范时，流程的第 2 步改为把它整理成 `source: user` 的风格，组件契约优先：沿用项目的表单、校验和日期组件，不从示例里搬第二套样式。评审重点也随之变化：真实的提交路径、接口出错时保留输入并定位字段、完成时显示接口确认的信息。
