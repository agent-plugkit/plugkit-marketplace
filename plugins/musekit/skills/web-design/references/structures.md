# 页面结构原型

结构原型回答「这个页面需要哪些区域、按什么顺序使用」。先按用户任务选原型，再用 style.md 的文法和本场景适配决定栏位、对齐轴、层级和窄屏重排。同一产品可以组合几种原型。

首屏是否要一整屏的主题区，由原型决定。只有「介绍与转化」需要先让访客看懂主题；其余四类页面的读者是来读、找、做或处理的，首屏直接进入内容本身，标题区只占几行，不把文章、结果、工作区或待处理事项推到一屏大标题之下。style.md 的首屏做法用在这类页面上时，借它的字体、对齐轴和强调色排标题区，但压缩标题区的高度，让内容在首屏露出；交付说明里写明这项调整。

## 介绍与转化

落地页、活动官网、产品首页：让访客快速明白这是什么，并采取一个行动。

- **区域**：导航、首屏（主题与一句说明）、关键信息（时间、地点、价格或核心卖点）、内容章节、行动入口、页脚。
- **使用顺序**：首屏看懂主题 → 找到关键信息 → 按兴趣读章节 → 行动。
- **关键判断**：首屏让人知道主题和下一步；关键信息不要藏进章节深处；只按内容需要设置章节，不自动堆砌营销区块。

## 阅读与理解

文章、报告、文档：按论述顺序读完一个主题。

- **区域**：标题区、章节导航、正文、图文穿插。
- **使用顺序**：标题 → 导读 → 正文顺序阅读，可以跳到章节。
- **关键判断**：版面跟随论述顺序；正文行长适合阅读，图像服务论证。首屏在标题区之后就能读到导读或正文的开头。

## 寻找与比较

目录、列表、作品集：在多个条目中找到并选择。

- **区域**：筛选与搜索、结果集合、详情预览、空状态。
- **使用顺序**：缩小范围 → 扫描 → 查看详情。
- **关键判断**：元数据密集时用对齐的行，图像决定选择时让图像获得面积；保留筛选结果和清除入口。筛选和第一批结果都在首屏。

## 完成任务

表单、预约、编辑器：一步步完成连续的操作。

- **区域**：主工作区、步骤或上下文栏、反馈区。
- **使用顺序**：输入 → 校验与反馈 → 完成或恢复。
- **关键判断**：每一步的输入、反馈和恢复方式优先于装饰；主操作的位置保持稳定。主工作区从首屏开始，进入页面就能开始第一步。

## 监控与处理

仪表盘、工作队列：先发现异常，再处理。

- **区域**：待处理事项、汇总、详情面板。
- **使用顺序**：异常 → 处理 → 背景统计。
- **关键判断**：先呈现待处理事项与异常，再呈现统计；状态不能只靠色块表达。待处理事项在首屏，不放欢迎横幅。
