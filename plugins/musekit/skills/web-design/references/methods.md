# 界面方法：把风格落进可用的界面

## 把风格转成界面选择

style.md 的手法要先翻译成界面行为，再落到组件上。

- **大字与对比**：可用于区分页面主题和工具区；重复条目的正文仍需要稳定字号，不把所有列表项做成海报标题。
- **克制的强调色**：用于当前选择、主操作或真正重要的反馈。状态较多时用标签、图标和位置补充，避免一色多义。
- **非对称**：让主工作区与背景信息的面积反映任务重要性。窄屏按优先级重排，不能仅等比缩小。
- **动效**：让元素移动解释状态变化，例如详情展开与筛选反馈。耗时操作要有进度或结果信息，不能只做装饰循环。
- **材质与图像**：在内容需要时使用。品牌照片和手绘图可以增加辨识度，表单与数据表仍需清楚的边界和文字。

## 先有真实文字，再调布局

用用户实际语言和内容检查长标题、长数字与多行说明。字体加载后检查断行；让容器随正文增长，给可截断内容提供明确的查看方式。中文标题不依赖仅含拉丁字形的展示字体。

为关键操作定义可见反馈和恢复路径。例如筛选为空时显示当前筛选及清除入口；保存失败时保留输入。示例中没有异步请求，就不伪造成功的网络操作。

表单只收 Brief 列出的字段。Brief 没写时，订阅只收邮箱，报名在邮箱之外加称呼，按人数限额的活动再加人数；不收电话和地址。时段、类别这类选项按 Brief 的内容给，不算额外字段。

## 滚动定位

- **吸顶导航会挡住滚动目标。** 导航吸顶时，在 `html` 上设 `scroll-padding-top` 等于导航高度，锚点跳转和出错后聚焦的字段才不会落在导航下面。
- **停顿放在章节外面。** 章节之间的大间隔用 `margin`，不用章节自己的 `padding`，否则锚点会落在空白的停顿里。
- **竖排元素不作滚动目标。** `writing-mode: vertical-rl` 的元素，`scrollIntoView` 的 block 方向是水平的，竖排章节名作锚点时页面不会纵向滚到它。锚点和 `scrollIntoView` 指向它所在的横排容器（整个章节）。

## 平板与矮视口

style.md 的本场景适配主要按桌面和手机写。两者之间和高度不足时，按下面三条处理：

- **行长优先于栏数。** 适配同时给出栏数和每行字数时，以字数为准，栏数按字数推算；断点里的外边距和字号先取 `tablet` 断点的 token。
- **窄一档的标题不比宽一档大。** 断点下用 `fit` 推出的流式字号，在断点上沿最大；它大于断点以上版面的标题时，用 `min()` 封顶。
- **矮视口只保证关键内容。** 视口高度不足约 800px（笔记本、横屏平板与手机）时，首屏保证标题、关键事实和主操作可见；版权行、装饰和次要信息可以移到首屏以下。焦点图像按高度裁切或换成横向构图，不压成窄条。

## 在浏览器验证

先执行主任务，再看目标窄屏与内容极值。确认键盘能到达操作、焦点可见、状态说明可读取，尺寸变化没有藏起关键信息。若动效承载状态转换，检查 reduced-motion 下仍可理解。

项目已有组件库和接口时，沿用项目的表单、校验和日期组件，评审重点随之变成真实的提交路径：接口出错时保留输入并定位到字段，完成时显示接口确认的信息。

对照实际页面判断是否完成：层级是否清楚、密度是否适合工作、视觉重点是否服务任务。检查清单不能替代观看和使用。

## 任务路径脚本

检查脚本的 `--flow` 接收一个 ES 模块，默认导出一个异步函数，参数是 `{ page, viewport, shot, check, log }`。`page` 是已经加载好、字体就绪的 Playwright 页面；`viewport.tag` 形如 `375x812`，桌面和手机的操作不同时按它分支。`shot(名字, { fullPage, selector })` 把截图存成 `review/flow-<视口>-<名字>.png`；`check(名字)` 在当前状态下重做遮挡、裁切和溢出检查，结果进报告；`log(...)` 记一行文字。脚本出错时，报告记下错误，其他检查照常完成。

```js
export default async ({ page, shot, check, log }) => {
  await page.click("#signup button[type=submit]");          // 空提交
  log("focus after error", await page.evaluate(() => document.activeElement.id));
  await shot("error", { selector: "#signup" });
  await page.fill("#name", "林");
  await page.fill("#email", "lin@example.com");
  await page.click("#signup button[type=submit]");
  await shot("done", { selector: "#signup" });
  await check("done");
};
```

风格跟随系统深浅色时，检查脚本只用浅色跑任务路径。要看某个状态在深色下的样子，在脚本里切换后再截：`await page.emulateMedia({ colorScheme: "dark" })`，`shot` 完再切回 `"light"`。

只写本页面独有的操作：打开页面、等字体、截首屏和整页、扫描宽度都由检查脚本完成。截图前要先把状态滚进视口，比如吸顶导航可能挡住出错的字段。有意裁切或纯装饰的文字（比如跑马灯条带）加上 `data-inspect-ignore`，它就不再出现在裁切的发现里。贴片这类压在别的内容上的元素不要加：加了以后，它盖住文字也不会再报。贴片压住的是板而不是字时，本来就不会有发现。
