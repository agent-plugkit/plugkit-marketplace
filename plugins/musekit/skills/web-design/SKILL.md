# Web Design

把用户要完成的任务组织成可用、清楚、有辨识度的界面，并交付可运行的代码。用户只要设计方向或方案时，按其范围交付。全程守住[底线](../../references/critique.md#底线)。

## 范围

- 网站、落地页和 Web App 界面，交付在浏览器里能运行、能操作的代码。
- 只要一张不需要交互的宣传图时交给 `graphic-design`；演示文稿交给 `slides-design`。

## Brief → 风格 → 结构 → 实现 → 评审

1. **写 Brief。** 先读现有项目：页面、组件、技术栈、设计系统和项目规则。然后回答：
   - 谁来，进入页面后要看懂什么、完成什么。
   - 主操作是什么，完成后给出什么反馈。
   - 涉及哪些状态：加载、空、错误、选中、完成。
   - 目标视口：至少一个桌面宽度和一个手机宽度。
   - 外观：风格有浅色和深色两个变体时，页面跟随系统深浅色，还是只要其中一种。项目已经跟随系统的，沿用它。
   - 怎样算成功：2–3 条可以检查的标准，其中至少一条是走通一条任务路径。

   缺少必需事实时询问用户；用户要求直接做时，可以创作的内容（项目、日程、文案）标为示例，不能编造的事实（网址、电话、价格、身份）留空，并在交付里列出。Brief 写在对话里就够了，不需要单独成文件；必须逐字准确的事实另存成一行一条的 `facts.txt`，第 5 步的检查会用到。完成标准：每个问题都有答案、标为示例，或列为待补。
2. **取风格。** Brief 写完后再取，用户点名了风格也一样：变体和约束要从 Brief 里来。项目已有设计系统时，把它交给 `musepool` 整理成 `source: user` 的风格，已有的组件契约优先；否则带上场景 `web`、Brief 里的气质与约束调用 `musepool`。得到作品目录里的 `style.md`，按[使用 style.md](../../references/style.md)使用。跟随系统时不传 `--variant`，只要一种外观时传那个变体。完成标准：`style.md` 已写出。
3. **选结构并用文法排它。** 从[页面原型](references/structures.md)中按任务选一个或组合几个，列出区域和使用顺序。再按 style.md 的文法和本场景适配，为桌面和手机分别决定每个区域的栏位、对齐轴、层级和重排方式。完成标准：每个视口的区域与栏位分配都已定下。不需要写成文件，交付说明里用几句话交代栏位决定。
4. **实现。** 沿用项目的技术栈和组件。接入 style.md 的 `:root` 变量（项目已有 token 体系时做映射），加载字体，并按[界面方法](references/methods.md)处理真实文字、状态与动效。完成标准：页面在本地运行，主任务路径可以操作。
5. **评审。** 按[评审循环](../../references/critique.md#评审循环)检查。先跑插件的检查脚本（插件根目录是本文件往上两级；在能解析 Playwright 的目录里运行，缺少时它会打印安装命令）：

   ```bash
   node <插件根>/scripts/inspect_page.mjs index.html --viewports 1440x900,768x1024,375x812 --facts facts.txt --flow flow.mjs
   ```

   它在每个视口截首屏、整页和灰度整页；style.md 跟随系统深浅色时，每个视口再用深色截一次首屏和整页（`web-<视口>-dark-*.png`），第一个视口按深色调色板查颜色，深色和浅色截图一模一样时会报出来；在固定宽度、style.md 断点的两侧和几档矮视口（如 1366 × 768、375 × 667）扫描横向溢出、文字遮挡和裁切（按字形的实际笔画判断，行高为 1 的大字不会误报），以及滚动时从吸顶导航下透出来的正文，矮视口另各截一张首屏；它还会走一遍 Tab 顺序、检查 reduced-motion 下仍在播放的动画、动画结束后仍不可见的首屏文字和 `transition: all`，并报出实际渲染的字体（网页字体附页面已加载的字重）和 style.md 之外的颜色。`--flow` 是可选的主任务路径脚本，写法见[界面方法](references/methods.md#任务路径脚本)。截图、`report.json` 和状态截图都写进 `review/`，终端只打印摘要。style.md 有「机检」一节时，先按它给元素加 `data-mk`，摘要里会列出每条版式规则量到的数值；这些规则不用再自己写代码量。本媒介的清单是：
   - 走通主任务，桌面宽度和手机宽度都看（任务路径脚本在第一个和最后一个视口各跑一次）。
   - 键盘能到达所有操作，焦点可见；状态不只靠颜色区分。
   - 字体加载后检查长标题、长数字和中文断行。
   - 动效承载信息时，在 reduced-motion 下仍然能理解。
   - 状态切换（出错、完成、展开）后截图确认实际渲染结果，不只检查 `hidden`、`aria-*` 这类属性。
   - 跟随系统深浅色时，深色截图同样过一遍：焦点、选中和出错状态看得清，玻璃、阴影和图片在深色底上没有变成脏灰块；主要状态在深色下也截一张（写法见[界面方法](references/methods.md#任务路径脚本)）。

   完成标准：按所在档位走完评审，没有实质问题。

## 交付

交付代码、查看入口和 `style.md`。交付说明写出 Brief 的要点、栏位决定、走通了哪条任务、检查了哪些视口和状态、评审走的档位，以及风格状态（`draft` 时写明）。浏览器或运行环境不可用时，交付现有代码并写明没有做视觉验证。

完整的判断过程见[制作示例](references/examples.md)。
