# 图位与路由

先收集关系图，再默认补上题图和确实帮助记忆的示意插画。技术文不能只剩流程图。不按每个标题配一张，也不设张数上限。用户没说「要封面」时，大纲里仍然要出现建议的插画，确认时可以去掉。

## 必做的关系图

每个非空 Mermaid 围栏都是图位。不跳过，不合并，不改写围栏里的关系。空围栏跳过。

散文里还有这些，也做成关系图，交给 `diagram-design`：

- 读者要同时看清两侧的对比
- 流程、结构或因果，文中还没有围栏

从散文抽出关系时，只使用原文已有的步骤和条件。大纲记下对应原句。

## 默认建议的插画

这些图走 `graphic-design`，不套关系图的密度清单。大纲里单独写明种类是「题图」或「示意插画」。用户没开口也要列出。说「直接做」时把它们算进假定，并在动手前说出来。用户说不要题图、不要封面或不要插画时，去掉对应图位。

**题图，默认一张。** 放在标题之后、第一段正文之前，让读者先知道文章在讲什么。原文开头已经有题图或封面时不重复做。它不复述后面流程图里的节点。只有用户明确要公众号封面裁切时才用 2.35:1；否则宽 1080px，高度按构图，不裁成固定 16:9。

**示意插画，按抽象判断来，不按标题来。** 一个读者需要记住、但步骤图表达不了的判断，收成一张图。画面用物件或场景指这个判断，交给 `graphic-design`。同一事实已经有关系图时，不为它再配一张同义插画。

## 比喻和插画的分界

先看这句话在让读者理解什么，再决定画不画、画成哪种。

| 原文在做什么 | 画什么 | 交给谁 |
| --- | --- | --- |
| 给出步骤、结构、对比或因果 | 这些关系 | `diagram-design` |
| 用比喻把关系说活，关系本身已经要画 | 只画关系，不画喻体 | `diagram-design` |
| 一个抽象判断没有步骤可画，比喻只是在帮忙记住 | 画判断，不画喻体 | `graphic-design` 示意插画 |
| 比喻本身没有需要记住的判断 | 不新增 |  |

「回滚像电锯切西瓜」：电锯和西瓜不画。回滚回到校验是关系，用已经有的流程图表达，不再配一张工具插画。

「编排只是把事情交出去，不是坐在总控台前」：不画控制室。若文章没有另一张图已经说明这层分工，就建议一张示意插画：一份目录把工作分到几张工作台。总控台、仪表和字面比喻里的物件不出现。

## 不新增

- 把比喻画成字面物件
- 为每个标题补一张
- 把已经写清的段落，或已经有关系图的事实，再画成氛围图
- 用文中没有的数字做统计图

作者原文里已有的图片保留，不重新生成。已有图片如果不是开篇题图，不代替默认题图。

## 路由

| 图位 | 场景 Skill | 路径 |
| --- | --- | --- |
| Mermaid，或散文里的流程、架构、状态、因果 | `diagram-design` | [密度](density.md) |
| 题图、示意插画 | `graphic-design` | 该 Skill 自己的规则：准确文字用排版，摄影和材质用生图。不因为关系图密度高就改走 HTML 图解 |
| 文中有表格或数据文件，图要呈现这些数据 | `scientific-figure` | 不生图，不补造数据 |
| 正文里只有两三个数字，没有表 | 不新建数据图 | 数字留在文字里，或作为关系图标签 |
