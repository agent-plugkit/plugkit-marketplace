# Diagram Design

让读者能追踪图里的每一条关系：谁到谁、什么条件、什么含义。Mermaid 或用户的说明是语义来源，版面、节点形态和表达方式围绕内容重新设计。默认交付可编辑的离线 HTML 与完整 PNG；用户只要方案时，停在对应的步骤。全程守住[底线](../../references/critique.md#底线)。

## 范围

- 位置表达关系、顺序或流程的图：系统架构、部署边界、流程与决策、交互时序、状态迁移、数据流与事件流，以及科学过程示意（实验步骤、装置流程、分流与汇合）。
- 位置由数值决定的图（柱、线、散点、分布）交给 `data-figure`。一张图里既有数据面板又有示意面板时，由它拼版，示意面板在这里做。
- 需要插画、物件隐喻或摄影质感来表达的请求交给 `graphic-design`。本 Skill 不生成整图图像。

## Brief → 风格 → 结构 → 制作 → 评审

1. **写 Brief。** 回答五个问题：
   - 读者想弄清什么问题：对照[结构原型](references/structures.md#从读者的问题选择表达)的第一列。
   - 来源里有哪些实体、关系、方向、条件、分组、顺序和注释：逐项列成核对清单。相同 label 不一定是同一实体，重复消息不因文字相同而合并；`~~~`、布局方向和样式配置是排版提示，不画成关系。
   - 在哪里被看到：文章、文档、幻灯片或打印，目标宽度或固定尺寸。图会被缩放到某个宽度显示时（插进 Word、PDF 或文章正文），记下这个宽度，按下面「信息与空间」推出画布宽度。嵌入自带图注的文档时，图题可以交给文档的图注，不在图里重复。
   - 来源缺什么：异常处置、通知方式、部署位置等不明的事实列为缺口，不补造。
   - 怎样算成功：2–3 条可以检查的标准。

   完成标准：核对清单已写出，缺口已问用户，或在用户要求直接做时列进交付说明。
2. **取风格。** Brief 写完后再取，用户点名了风格也一样。带着场景 `diagram`、Brief 里的气质和约束调用 `musepool`，得到作品目录里的 `style.md`，按[使用 style.md](../../references/style.md)使用。完成标准：`style.md` 已写出，变体已定。
3. **选结构并用文法排它。** 从[结构原型](references/structures.md)中按读者的问题选一种图型；用户已经选定图型或给了完整 Mermaid 时，围绕它组织。再按[用风格文法排它](references/structures.md#用风格文法排它)和 style.md 的本场景适配，决定阅读入口、各分区的主次面积、节点角色的形态、主路与支路和回路的线型与颜色、线槽的位置。完成标准：写出一份版面说明，每个分区有位置和面积级别，每类关系有线型和颜色。
4. **制作。** 按[制作说明](references/html.md)和[接入协议](references/protocol.md)写 HTML，各图型的接法见[接入示例](references/integration.md)：DOM 和 CSS 负责文案与视觉，值取自 style.md；JSON 只声明关系。新图显式设置 `portDistribution: "spread"` 与 `layout: "tidy"`；修改旧图时保留它原有的设置。测量、走线、诊断和编辑器由随 Skill 提供的运行时完成，不重写，不调用 Mermaid CLI，不把 Mermaid 默认图换肤当作设计。完成标准：交付命令通过，或按下面的返回约定交付未验证的 HTML。
5. **评审。** 按[评审循环](../../references/critique.md#评审循环)检查，本媒介的清单是：
   - 对照第 1 步的核对清单：每个实体、关系、条件和注释都在图上，方向和端点正确；分支、异常、回路、时序和旁注与主路径同样完整。
   - 打开导出的 PNG：文字不截断、不遮挡，标签贴着自己的线；线条、箭头和起止标记在经过的每种背景上都看得见。
   - 分组外框只圈住真实的成员，不用相交框线暗示来源里没有的归属。
   - 按目标展示宽度缩放后，节点正文和连线标签仍读得出。
   - 运行时的布局提示逐条处理，或写明保留的理由。

   走完整档时，交给评审者的报告用 `--strict` 重跑一次，让它能看到全部提示，而不是被默认策略过滤后的结果。

   完成标准：按所在档位走完评审，没有实质问题。

## 三个命令

准备命令在任何目录都能运行。检查和交付命令要从装有 Playwright 的工作目录运行，脚本写成它在本 Skill 里的实际路径；下面的相对路径以本 Skill 目录为准。

```sh
python3 scripts/prepare_diagram.py artwork.html --output artwork.editable.html
node scripts/inspect_diagram.mjs artwork.editable.html --output checks
node scripts/deliver_diagram.mjs artwork.html --output artwork.editable.html --json
```

- **准备**只要 Python 3：检查重复 ID、缺失端点和未内嵌资源，再内联运行时，得到可以离线打开的 HTML。
- **检查**需要 Node.js、工作目录里的 Playwright 和浏览器：离线打开成品，导出完整 PNG，保存重开，写出 JSON 报告。它不移动模块，也不改文案。
- **交付**把准备和检查串起来，全部通过后才替换目标 HTML，推荐使用。加 `--strict` 时布局提示也阻断交付。

返回约定：

- 退出码 `0` 交付完成；`1` 检查、读取或交付失败；`2` 参数错误或缺少运行依赖。`--json` 时标准输出只有一个结果对象。
- 通过时，PNG、受检 HTML 副本和报告在输出旁的 `<名称>.checks/<批次ID>/`。交付给用户的 PNG 从最终批次复制到 HTML 旁边，交付说明写明批次 ID。用结果里给出的路径核对，不拿别的批次当证据。报告的 `passed` 只代表程序检查；`notChecked` 列出仍要你看的语义和视觉项。
- 缺少 Playwright、浏览器，或浏览器被沙箱阻止时，结果是 `verified: false`，并带 `html`、`cause`、`message` 和 `fix`。交付那份 HTML，把 `message` 和 `fix` 原样告诉用户，说明 PNG 没有导出、浏览器检查没有执行；不另找办法声称通过。

参数、批次和并发锁的细节见[验证后交付](references/html.md#验证后交付)。

## 信息与空间

- 画布由内容、媒介和可读字号决定。图会被缩放显示时，缩放系数 = 显示宽度 ÷ 画布宽度；图里最小的字（通常是 `size-meta`）乘以这个系数后，屏幕上不小于 12 px，打印不小于 7 pt（约 9.3 px，按 96 dpi 计）。由此反推画布宽度的上限：画布宽 ≤ 显示宽度 × `size-meta` ÷ 最小字号。例如中文 Word 的 A4 默认版心宽约 14.6 cm（约 553 px）、`size-meta` 13 px、打印时，上限是 553 × 13 ÷ 9.33 ≈ 770 px，取间距阶梯上不超过它的值（如 768）。画布比 style.md 的参照画布窄时，字号照用 token，不跟着缩；`margin`、`gutter` 改取阶梯上与画布相称的值。没有指定尺寸时允许增长；固定尺寸放不下时，先改阅读方向、分区、换行和走线，仍放不下就向用户提出扩大画布或总览加详图的具体取舍。拆图、删减或改变含义要用户确认，不缩成难读的小字。
- 节点尺寸来自实测内容：不按字符数估算宽度，不手算端点。自动走线失败说明空间不够，调整空间，不忽略提示。
- 每一条关系都能回答「谁到谁、什么条件、什么含义」；只靠相邻位置而没有明确语义的分组不算完整表达。

## 交付

交付原始 `.mmd` 或来源说明、`style.md`、自包含的可编辑 HTML 和完整 PNG。HTML 默认是阅读模式，可以查找节点、聚焦直接关系；点击「编辑布局」可以微调位置、尺寸、端口、折点和标签，[操作说明](references/editor.md)解释保存与导出。用户要求其他格式时，只提供实际支持的导出。

说明关键的设计选择、风格状态（`draft` 或未验证适配时写明推导了哪些决定）、来源缺口、评审走的档位，以及程序检查和目视检查各做了什么、还有什么限制。

完整的判断过程见[制作示例](references/examples.md)。
