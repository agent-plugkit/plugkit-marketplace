# 图解结构原型

结构原型回答「这张图要让读者追踪什么、按什么顺序读」。先按读者的问题选原型，再用 style.md 的文法和本场景适配决定分区面积、节点形态、线型和留白。同一原型在不同风格下会长得完全不同；不按节点数量套统一模板。

## 从读者的问题选择表达

用户已经选定图型或给出完整 Mermaid 来源时，围绕其选择组织，不自动转换。下表是起点，不是必须套用的视觉模板。

| 读者的问题 | 推荐表达 | 必须保留 | 不适用情况与事实缺口 |
| --- | --- | --- | --- |
| 系统里有哪些部分，如何连接？ | 系统总览，按职责分区 | 组件、接口方向、外部依赖、系统边界 | 精确调用顺序应使用时序；未知依赖不能补造。 |
| 组件部署在哪里，什么跨越边界？ | 部署与边界图，区域嵌套 | 部署位置、所属网络、已知归属、跨区连接 | 部署事实不明时先画逻辑架构，不能猜地区或负责人。 |
| 一件事经过哪些判断，失败后去哪里？ | 流程或决策图，阶段与条件分支 | 条件、全部出口、回路、明确的责任角色 | 只关心对象状态时改用生命周期；缺少异常处置就指出缺口。 |
| 谁先调用谁，返回什么？ | 同步交互时序 | 参与者、消息方向、请求与返回、分支和顺序 | 无时间顺序的依赖关系用架构；不能凭箭头位置添加调用先后。 |
| 请求返回之后，后台如何完成工作？ | 异步往返时序 | 接收确认、队列交付、后台处理、结果写入、通知或查询 | 不知道通知或轮询方式时不能任选一种；只问队列拓扑时用事件流。 |
| 数据从哪里来，经过什么变化，被谁使用？ | 数据流与血缘图 | 数据资产、变换、来源与去向、敏感数据边界 | 请求延迟或调用顺序用时序；缺少字段级事实时不宣称字段血缘。 |
| 哪些事件经过哪些 Topic 和消费者？ | 事件流拓扑 | 已知事件、生产者、Topic、消费组、失败及重放路径 | Topic、消费语义不明时先用通用流程；不得补写重试、幂等或投递保证。 |
| 对象能处于哪些状态，如何转换？ | 状态生命周期图 | 初始与终止、事件或条件、取消、重试和等待 | 跨角色行动顺序用流程；不能将操作动作当作已确认状态。 |
| 一个实验或装置流程怎样进行，物料去了哪里？ | 科学过程示意，按步骤或装置分区 | 步骤顺序、分流与汇合、每一路的去向、给定的条件（时间、温度、转速） | 图中位置表达的是测量值时，交给数据图；没有提供的机制、比例尺和数据曲线不添加。 |

数据流和异步往返的完整来源及成品见[接入示例](examples.md)。选好表达方式后仍需逐项核对来源；「先总览」不授权删除其他信息。

## 各图型的起点

| 图意 | 一种有效起点 | 必须仍能读到的关系 |
| --- | --- | --- |
| 系统架构 | 按职责分栏或分区，分配主次面积；跨区接口单独留出走线带 | 系统边界、接口来源与去向、反馈回路；不能只有组件名单 |
| 决策过程 | 按判断阶段组织，优先规则、命中结果和未命中路径分别呈现 | 判断条件、先后顺序、所有出口与回到哪一步 |
| 交互时序 | 参与者作为泳道，消息沿时间方向展开；分支作为独立事件区 | 请求与返回、消息顺序、自调用、分支条件与备注 |
| 状态迁移 | 突出活跃状态，按转换含义组织去向，回路获得独立空间 | 源状态、目标状态、触发条件、初始/结束含义与自循环 |
| 科学过程 | 步骤沿一条主阅读方向排开，分流处让每一路有自己的区域，条件写在步骤或连线上 | 每一步的输入与输出、分出的每一路去向、哪一路进入后续步骤 |

决策图可以使用规则行而不画菱形：将「满足条件 → 结果」「否则 → 下一规则」明确写在对应位置。架构图也可用接口条带代替漫长折线，只要每条条带清楚标出来源、去向和含义。重组表达时逐项核对来源，不能用漂亮的组件分栏省掉连接关系。

## 科学过程示意

科学过程示意解释已有的步骤和关系，不呈现测量结果。

- 页眉或图注标明「概念示意」；不画刻度、比例尺和数据曲线，图形尺寸不能让人读成实际尺寸。
- 器具和物料可以用简单轮廓或带名称的节点表达；轮廓用 SVG 时外框与内容分开标记（见[接入协议](protocol.md)），文字由作者显式分行。复杂的插画式器具交给 `graphic-design` 另做，不在这里生成图像。
- 分流时每一路都有标签和去向，弃去或保留的一路也画出来；只有资料里写明进入下一步的那一路才连过去。
- 资料没有给出的反应机制、条件和数值不补写；缺口写进交付说明。

## 从内容得到版面

先用用户给定的实际文字估计内容重量。长说明与短标题需要不同空间；分支多的区域需要更大面积或更长阅读路径。大标题、索引、图例和注释也属于版面，不能最后叠在节点上。

估计只用于初步分区。制作时必须等待字体、图片和文字排版完成，交由共用代码实测节点和标签。跨区带宽至少容纳实际标签及两侧留白；模块内先确定阅读宽度，再让高度容纳正文。页眉高度决定主体起点，不把标题区域当成可复用空白。几何提示出现时调整相关区域，不用统一卡片尺寸覆盖各类图各自的构图。

分组边界也在表达事实。重新构图后，外框不能把无关组的节点圈入，或用相交框线暗示来源中不存在的重叠归属。空间隐喻需要与真实成员关系一致；不能只让 DOM 分组正确而忽略画面中的边界。

## 用风格文法排它

style.md 的文法和本场景适配决定版面，不只决定颜色和字体。动手前先回答下面三件事，并写进版面说明：

| 需要决定的内容 | 可观察的结果 | 不算完成的做法 |
| --- | --- | --- |
| 阅读入口与空间组织 | 重心、阅读轴、分区比例或阶段组织按文法安排，并帮助读者追踪内容 | 沿用另一张图的布局，只改色值、画幅或外边距 |
| 节点角色与信息层级 | 输入、关键处理、判断、终态与旁注有符合文法的面积、位置或形态差异 | 所有节点统一加粗边框、阴影或换字体 |
| 关系表达与节奏 | 主路、支路、回流和注释有明确的线型、颜色和空间职责，标签与所属关系一起安排 | 用装饰箭头、编号或口号填满空白 |

- 用字号、字重和位置形成第一眼入口，再通过分区标题建立第二层阅读。
- 颜色承担职责，例如区分主流程、例外与回路，并且只用 style.md 的颜色和「文字配对」允许的组合；细线、直接标签和空间关系共同帮助读者追踪。
- 留白控制节奏，也给连线与说明留出空间。它不等于把节点缩小后散落在大画布上。
- 时序图的泳道与时间顺序、状态图的迁移含义必须保留；风格带来的变化发生在事件分区、角色层级、分支空间和注释组织上，不为求新打乱事实。
- 深浅色块混排时，沿整条路径检查线条、箭头和起止标记与背景的对比；标签可读不代表连线可见。必要时调整走线通道或色块边界；运行时每条关系只画一条线，不支持给线加描边。
- 系列图共用一份 style.md，同时按各自的图意改变结构。架构、决策和时序不需要长成相同的卡片网格。
- 大块空容器、重复的技术标签和印在图上的制作口号不产生设计质量。新增的说明都要能追溯到来源，不为填充版面补造缓存、通知、重试策略或服务保证。

## 对齐与让位

- 一对一前后相接的步骤放在同一行或同一列并对齐，间距一致；同一行同一角色的节点等高，同一列同一角色的节点等宽。分叉与汇合节点放在分支中间：风格要求强轴、不居中时，让这个节点横跨它的所有分支，一侧边缘压在轴上，中心自然落在分支中间。同一角色使用相同的外形样式，颜色可以用附加 class 区分，`layout: "tidy"` 据此整理。刻意横跨几列的节点不要和同列的普通步骤算作同一角色，否则整理会把普通步骤拉成一样宽：给它换一种标签（例如 `section`），或者不写 class、改用属性选择器写样式（见[接入协议](protocol.md#构图整理)对「同一角色」的定义）。
- 阶段之间需要分隔时用分组或阶段标题表达，不靠加大某一段间距。
- 对齐或标签需要空间时，整体移动后续区域，不把单个节点挪偏去躲避拥挤。
- 阶段编号、分隔线、图例等装饰放进页眉、页脚，或标为节点；留在主体或分组里的装饰会让旁边和后方的内容保持原构图。

## 密度与拆分

先尝试改变阅读方向、换行、区域比例或关系表达，再考虑扩展画布。固定尺寸下仍难以阅读时，给出具体的拆分建议：总览包含哪些系统，哪一部分进入详图，跨图关系如何标识。待用户确认后拆分，保留原始完整来源。

不能通过删掉异常分支、把多条条件合为「其他」、藏掉标签或无限缩字来声称解决了密度问题。
