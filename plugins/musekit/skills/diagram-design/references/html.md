# 自定义 HTML/CSS/SVG 制作

这里制作的是独立图解作品。HTML 用于排版和可编辑文字，SVG 用于关系、路径和图形；可按需要使用其中一种或组合。不要用 Mermaid CLI 导出，也不要把 Mermaid 默认 SVG 换色后作为完成品。

## 排内容，再画关系

1. 根据图意安排主区域、标题、图例和注释。优先让 CSS Grid、Flex 或 SVG 文本布局容纳真实内容；不要让说明文字被固定高度裁掉。
2. 确定字体、字号、行高与内容宽度，等待实际字体加载后测量尺寸。中文、公式、代码片段和长 label 需要各自合适的断行策略。
3. 再定位连接点与走线路径。HTML 节点可以在字体就绪后用 `getBoundingClientRect()` 计算相对于画布的锚点；内容或画布改变时重新计算。小图可以直接安排 SVG 坐标，仍需在修改文字后检查。
4. 给线条、箭头和 label 留出空间。箭头终点应指向明确的目标，跨区回路可以走外围或专用通道；连线标签有自己的位置，不能压住正文。

这些是局部制作技巧，不需要建立通用节点 schema、路由算法或新的渲染框架。只有当前图真的需要时才写辅助代码。

## 文字与交互

文本保留在可编辑的 HTML 或 SVG 层。背景纹理、插图与图标可以来自生成工具，但不承担精确业务文字与关系。使用自包含资源或确实可用的字体回退，避免导出时依赖消失的外链。

大图可以在 HTML 中提供缩放或滚动查看；导出的 PNG 仍需包含完整画布，不能只截取浏览器当前可见部分。若用户限制了最终尺寸，要在该尺寸下判断可读性。

## 浏览器检查与导出

使用当前环境允许的浏览器工具打开作品，等待字体与图像就绪。先看完整构图，再检查关键区域和目标展示尺寸；通过可见 DOM 或元素边界辅助检查截断和遮挡。

修正实际问题后，从最终画布截图或使用浏览器的可用导出能力生成 PNG。可按交付需要提高像素密度，但高像素不能挽救过小的字。重新打开导出的文件检查是否完整、清楚，尤其是长图底部、SVG 标记、注释和嵌入素材。

保留 HTML 与来源文件。用户需要 SVG/PDF 时，采用当前作品真实支持的导出方式，验证文字和资源能否正常显示；不要把截图包装成“可编辑 SVG”。

若工具只能保存屏幕范围的截图，就说明限制并使用该环境支持的完整画布导出方式；不能把被截断的截图当作完整交付。
