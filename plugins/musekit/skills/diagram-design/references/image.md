# 用户明确选择的整图生图

只有用户明确选择整图生图时使用。这条路径直接根据内容和视觉方向创作图片，不要求先做 HTML，也不把 HTML 截图当作必须复刻的模板。

## 制作

- 先评估信息密度：文字长度、分支、交叉关系、注释和目标尺寸共同影响成功率。若高密度与固定尺寸明显冲突，先给出具体取舍，让用户选择保持内容并增大画布、确认拆分，或调整表达方式。
- 提示词包含准确的必要文字、关系、方向、分组与阅读顺序，并说明整体视觉意图。可以主动设计帮助理解的物件、微场景或图形隐喻，但不增造流程步骤或事实。
- 让生成工具处理画面关系，不用逐像素坐标或大量 CSS 术语规定构图。用户提供的 seed 负责视觉启发，不提供业务内容。

## 核对与迭代

打开原尺寸图片，逐项核对文字、分支条件、连线、方向和旁注，再看目标展示尺寸。针对实际错误修改，保留已确认内容，不设机械的一轮上限或为了重试改变整个业务结构。

无法保真时，列出具体缺失或歧义，讨论继续修图、调整尺寸、经确认拆图或改用自定义 HTML。不要静默更换方式，不把“看起来有这些方框”当作语义完整。

## 小型示例

**请求**：用整图生图表现“收集 → 整理 → 展示”的三阶段创作流程，三个中文阶段名必须准确，不增加回路。

**选择**：为三个阶段分别设计收集盒、整理工作台和展墙的物件隐喻；保留清楚的前进方向，让阶段标题获得独立空间。

**交付**：实际图片和生成提示词；核对三个标题与两条有向关系。若文字或方向错误，修正后重新查看。
