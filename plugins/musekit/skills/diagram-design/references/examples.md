# 图解的完整制作示例

这些虚构场景提供独立的原始内容、构图选择与验收要点。先读取对应 `.mmd`，再设计作品；文件中的排版提示不等于业务关系。可使用[共享 seed](../../../references/seed-brief.md)的颜色职责，也可选择其他视觉方向。

每例包含精简制作源码与可直接打开的离线编辑成品。优先读取精简源码；成品内嵌运行代码，不必整段读入上下文。它们共用色彩关系，各自按内容确定构图；颜色、尺寸和布局不成为统一模板。

另有 [HTML 制作起点](../assets/starter.html)，覆盖长中文、长代码、两行代码标签、嵌套分组与自循环。按[制作说明](html.md)封装后可运行，修改宽度即可检查换行、测高与内容下限。

## 架构：素材处理服务

**输入**：[architecture.mmd](examples/architecture.mmd)。浏览器与批量导入进入接收 API，API 把素材放入存储并提交任务，Worker 消费任务、读取素材、写回索引，浏览器查询索引。

**精简源码**：[architecture.html](examples/source/architecture.html)。**可编辑成品**：[打开架构示例](examples/architecture.html)。

**为什么这样组织**：读者需要先理解职责边界，再追踪数据流。用“入口 / 处理 / 数据”三个不同面积的区域建立地图；处理区突出 API、队列、Worker 的链路。为浏览器查询和 Worker 读取素材留出独立路径或有明确端点的接口条带。

**制作**：自定义 HTML 分区与 SVG 连接；主路径与查询路径在文字和线型上可区分，图例解释这种区别。标注“相同任务号不重复提交”。`API ~~~ Q` 仅用于原图排版，不新增业务箭头。

**核对与交付**：七个实体、八条有含义的连接、三个分组及幂等说明均有对应表达；核对各箭头端点。交付来源、可编辑 HTML 与完整 PNG。

## 决策：借阅申请

**输入**：[decision.mmd](examples/decision.mmd)。先检查资料完整，再查库存，再判断预约，所有结果都有出口。

**精简源码**：[decision.html](examples/source/decision.html)。**可编辑成品**：[打开决策示例](examples/decision.html)。

**为什么这样组织**：条件较多但判断顺序清楚，适合按“申请 / 库存 / 预约”分阶段安排。满足与不满足的出口直接放在对应判断旁，补充资料的回路留在外围；不强迫所有判断都使用菱形。

**制作**：阶段标题、条件行和结果区形成层级；每个结果用完整短句呈现，候补与待补充不能只用颜色区分。为“补充后重新提交”的回路预留空间，读者能追踪到原起点。

**核对与交付**：八个实体、八条关系，资料缺失、库存不足、允许预约与暂不借出均保留。未限制尺寸时可增长画布；若用户限定小画幅，展示具体拆分建议后确认。

## 时序：资源预订

**输入**：[sequence.mmd](examples/sequence.mmd)。访问者、前端、服务、存储四个参与者，库存为零与大于零形成两个分支。

**精简源码**：[sequence.html](examples/source/sequence.html)。**可编辑成品**：[打开时序示例](examples/sequence.html)。

**为什么这样组织**：需要比较谁在什么时候发送了什么，采用四条泳道与从上到下的时间线。分支区域让失败和成功同等明确；说明置于独立注释带。

**制作**：保持九条消息的参与者端点和分支归属，区分请求与返回。提交、校验、占用、确认的次序由消息行保证，长标签获得自己的行高。

**核对与交付**：四个参与者、九条消息、两个分支及请求号注释完整；库存为零时不能出现占用操作。检查消息标签不与泳道标题或其他箭头重叠，再导出。

## 状态：异步任务

**输入**：[state.mmd](examples/state.mmd)。排队后进入运行，可成功、重试或耗尽；取消只允许发生在排队状态。

**精简源码**：[state.html](examples/source/state.html)。**可编辑成品**：[打开状态示例](examples/state.html)。

**为什么这样组织**：重点是运行期间的结果与恢复路径。突出 `running`，把成功、失败和排队后的取消分别安排；重试回到 `queued` 的路径有自己的弧线或外围线槽。

**制作**：用形态、标签和线型共同区分活跃状态与终态；“次数耗尽”和“可重试错误”都写在转换上，不能简写成一条模糊失败线。将“任务号唯一，状态变化写审计”放在可读的注释区。

**核对与交付**：五个命名状态、六条业务转换和三个终止转换，以及注释完整；成功、耗尽、取消的路径都可追踪。状态名字保留原始标识，解释文字可以分行。

## 视觉检查的反例

运行各例时依次检查：架构分组连同标题移动；密集决策分支与外围回路留有通道；时序参与者、生命线、消息行与分支同步；状态标签、折点、端口跟随。尝试拖动、修改尺寸、撤销重做、保存重开并导出完整 PNG。纯 SVG 的外框与内容分开，文字先由作者显式分行，再交给代码测量。

- 有三个系统栏目，却找不到 Worker 从哪里读取素材：画面有层级，关系仍不完整。
- 决策图省去“否”的出口来留白：遗漏信息，不是构图优化。
- 四张图共用等高卡片，只替换标题和色彩：没有根据图意组织内容。
- 状态图箭头漂亮，但重试指向 `running` 而非 `queued`：改变了来源含义。
- 只查看 HTML，没有打开导出的长图：尚未证明导出完整。

## 数据流：从事件到分析结论

**来源**：[dataflow.mmd](examples/dataflow.mmd)。**精简源码**：[dataflow.html](examples/source/dataflow.html)。**成品**：[打开数据流示例](examples/dataflow.html)。

七个节点、七条关系。先区分授权事件与丢弃路径，再以去标识模块为分流点展开仓库与聚合路径，最后汇入报表。模块尺寸按文字确定，左右路径留出标签空间；新图启用自动端点分散。核对未授权数据不流入处理区、原始标识不进入仓库，以及两条报表来源都存在。图中的数据处理规则仅属于这个虚构示例。

## 异步往返：请求返回之后，任务继续

**来源**：[async-roundtrip.mmd](examples/async-roundtrip.mmd)。**精简源码**：[async-roundtrip.html](examples/source/async-roundtrip.html)。**成品**：[打开异步往返示例](examples/async-roundtrip.html)。

五个参与者、十二条消息。从快速返回任务号、后台消费与写入结果，直到客户端按任务号查询。自调用独立保留，返回消息以虚线和完整文字表达。检查 202 返回发生在处理之前，结果写入先于读取；来源声明的是查询，不补画 webhook、重试或额外的交付保证。阅读面板可查找处理器并查看自调用及每条直接消息。
