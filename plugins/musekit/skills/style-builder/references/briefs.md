# 标准 Brief

每个场景一份固定的虚构请求。新 Template 都用它试做，不同风格的作品才能横向比较。内容全部虚构，作品上要有「虚构示例」的声明。

用法：

- 把请求里的 `<风格>` 换成新 Template 的名字，再附上它的路径（用户 Template）或 id（库内 Template）。
- 把请求原样交给对应场景的 Workflow，按 Workflow 自己的流程走，不额外提示风格怎么用。试做要检验的正是风格文件和 Workflow 能不能自己撑起作品。
- 必须逐字准确的事实已经整理成一行一条的 `facts.txt`，直接交给检查脚本的 `--facts`。图解、数据图和文章配图的事实就在原文和数据里，由 Workflow 自己的核对清单检查。
- 只试做一个场景时，从请求里删掉另一件作品，其余不改。
