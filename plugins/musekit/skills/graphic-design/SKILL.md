# Graphic Design

让一页作品有明确的焦点、阅读层级和表达目的。默认交付最终作品；用户只要方案或提示词时，停在对应的步骤。全程守住[底线](../../references/critique.md#底线)。

## Brief → 风格 → 结构 → 制作 → 评审

1. **写 Brief。** 回答五个问题：
   - 在哪里被谁看到：媒介、画幅和像素尺寸。
   - 读者先看到什么、接着读到什么、最后记住什么。
   - 哪些信息必须逐字准确：标题、日期、地点、署名、Logo。
   - 有哪些可用素材：照片、插画、品牌资产。
   - 怎样算成功：2–3 条可以检查的标准。

   缺少必需事实时询问用户；用户要求直接做时，可以创作的内容标为示例，不能编造的事实（网址、电话、价格、身份）留空，并在交付里列出。Brief 写在对话里就够了，不需要单独成文件；必须逐字准确的事实另存成一行一条的 `facts.txt`，第 5 步的检查会用到。完成标准：每个问题都有答案、写着「由我创作」，或列为待补。
2. **取风格。** Brief 写完后再取，用户点名了风格也一样：变体和约束要从 Brief 里来。带着场景 `graphic`、Brief 里的气质和约束调用 `musepool`，得到作品目录里的 `style.md`，按[使用 style.md](../../references/style.md)使用。完成标准：`style.md` 已写出，变体已定。
3. **选结构并用文法排它。** 从[结构原型](references/structures.md)中按内容选一个，列出它的区域和阅读顺序。再按 style.md 的文法和本场景适配，决定每个区域占哪几栏、对齐在哪条轴、层级靠什么建立、留白落在哪里。完成标准：每个区域的栏位、尺寸级别和阅读次序都已定下。不需要写成文件，交付说明里用几句话交代栏位决定。
4. **选路线并制作。** 按[制作路线](references/methods.md)判断排版优先、生图优先还是混合，然后制作。完成标准：HTML 作品按目标尺寸完成，PNG 由第 5 步的检查脚本导出；生图作品已经导出目标尺寸的文件。
5. **评审。** 按[评审循环](../../references/critique.md#评审循环)检查。HTML 作品先跑插件的检查脚本（插件根目录是本文件往上两级；在能解析 Playwright 的目录里运行，缺少时它会打印安装命令）：

   ```bash
   node <插件根>/scripts/inspect_page.mjs poster.html --canvas 1080x1440 --facts facts.txt
   ```

   它等字体加载完成后，把目标尺寸的 `poster.png` 导出到 HTML 旁边，并在 `review/` 里留下灰度图、0.25 和 0.35 倍预览和 `report.json`。终端只打印摘要：实际渲染的字体、每条事实的出现次数和字号，以及遮挡、裁切、出画布等发现。需要细节时再读报告。作品画在 canvas 上、需要等脚本画完时，加 `--ready` 传等待条件。生图作品没有 HTML，直接看导出的图。style.md 有「机检」一节时，先按它给元素加 `data-mk`，摘要里会列出每条版式规则量到的数值；这些规则不用再自己写代码量。本媒介的清单是：
   - 在目标尺寸和缩略图尺寸下，标题都读得出，并且只有一个焦点。社媒图在信息流缩略里约按 0.25 倍显示，标题要在这个尺寸读得出；点开全屏约按 0.35 倍显示，日期、地点等关键事实要在这个尺寸读得出，所以至少用 `size-body`，`size-meta` 只放读不清也不影响理解的附注。
   - Brief 中必须准确的信息逐字正确。
   - 留白成块、有意图；字和图的关系不遮挡核心文字与主体。
   - 生成的图像通过底线里的逐项核对。

   完成标准：按所在档位走完评审，没有实质问题。

## 交付

交付成品（PNG 或用户要求的格式）、可编辑的源文件和 `style.md`；使用生图时附上最终提示词。交付说明写出 Brief 的要点、栏位决定、关键的设计选择、风格状态（`draft` 时写明），以及评审走的档位和实际检查了什么。

完整的判断过程见[制作示例](references/examples.md)。
