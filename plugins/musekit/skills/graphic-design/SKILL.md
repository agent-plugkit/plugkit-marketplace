# Graphic Design

让一页作品有明确的焦点、阅读层级和表达目的。默认交付最终作品；用户只要方案或提示词时，停在对应的步骤。全程守住[底线](../../references/critique.md#底线)。

## Brief → 风格 → 结构 → 制作 → 评审

1. **写 Brief。** 回答五个问题：
   - 在哪里被谁看到：媒介、画幅和像素尺寸。
   - 读者先看到什么、接着读到什么、最后记住什么。
   - 哪些信息必须逐字准确：标题、日期、地点、署名、Logo。
   - 有哪些可用素材：照片、插画、品牌资产。
   - 怎样算成功：2–3 条可以检查的标准。

   缺少必需事实时询问用户；用户要求直接做时，可以创作的内容标为示例，不能编造的事实（网址、电话、价格、身份）留空，并在交付里列出。完成标准：每个问题都有答案、写着「由我创作」，或列为待补。
2. **取风格。** 带着场景 `graphic`、Brief 里的气质和约束调用 `musepool`，得到作品目录里的 `style.md`，按[使用 style.md](../../references/style.md)使用。完成标准：`style.md` 已写出，变体已定。
3. **选结构并用文法排它。** 从[结构原型](references/structures.md)中按内容选一个，列出它的区域和阅读顺序。再按 style.md 的文法和本场景适配，决定每个区域占哪几栏、对齐在哪条轴、层级靠什么建立、留白落在哪里。完成标准：写出一份版面说明，每个区域都有栏位、尺寸级别和阅读次序。
4. **选路线并制作。** 按[制作路线](references/methods.md)判断排版优先、生图优先还是混合，然后制作。完成标准：导出目标尺寸的成品文件。
5. **评审。** 按[评审循环](../../references/critique.md#评审循环)检查，本媒介的清单是：
   - 在目标尺寸和缩略图尺寸下，标题都读得出，并且只有一个焦点。
   - Brief 中必须准确的信息逐字正确。
   - 留白成块、有意图；字和图的关系不遮挡核心文字与主体。
   - 生成的图像通过底线里的逐项核对。

   完成标准：最后一轮评审没有实质问题。

## 交付

交付成品（PNG 或用户要求的格式）、可编辑的源文件和 `style.md`；使用生图时附上最终提示词。说明关键的设计选择、风格状态（`draft` 时写明），以及评审实际检查了什么。

完整的判断过程见[制作示例](references/examples.md)。
