# musepool — 离线设计灵感库

LLM 自己决定设计细节时,会退回它见过的平均值:视觉同质化、技术浅薄。解药是**外部参照 + 显式配方**——动手之前,先从本地种子库取回真实的设计先例,再把借用的约束、主动改变和最终检查锁进 recipe。

本库内置 **29 个优质种子**,覆盖 5 种场景,每个种子含完整 seed——叙事/布局/字体/色彩/动效/工艺等维度,均写到实现级细节(具体色值、字号、CSS 参数、交互逻辑);部分种子另附代码级深度参考(文末 `Dimensional References`)。全部在本地 `seeds/` 目录,无需任何网络、账号或后端。

## 场景区位

| 场景 | 目录 | 适用 | 建议重点维度 |
|---|---|---|---|
| 前端开发 `frontend` | `seeds/frontend/` | 网站、Web App、落地页、桌面工具应用、交互体验 | layout, typography, motion, color, components |
| 海报 `poster` | `seeds/poster/` | 海报、活动视觉、封面、单屏大字构图 | typography, layout, color, imagery |
| 信息图 `infographic` | `seeds/infographic/` | 信息图、数据报告、仪表盘、年报 | layout, components, color, typography |
| 社媒图文 `social` | `seeds/social/` | 社媒帖子、分享卡片、品牌图文 | color, narrative, layout, imagery |
| 学术插图 `academic` | `seeds/academic/` | 论文图表、科学可视化、标注示意图 | imagery, craft, layout, color |

## 工作流:广搜 → 定 wow → 取深 → 锁 recipe → 实现 → 检查

配套脚本 `scripts/muse_local.py`(纯标准库,Python 3.9+ 可跑):

```bash
python3 scripts/muse_local.py list --scenario poster          # 列出某场景全部种子(浅摘要)
python3 scripts/muse_local.py search "monochrome grid"        # 跨场景关键词检索
python3 scripts/muse_local.py search "dashboard" --scenario infographic
python3 scripts/muse_local.py show <id或文件名片段>            # 打印完整 seed + 深度参考
python3 scripts/muse_local.py recipe <id> [<id> ...] --brief "原始需求"
python3 scripts/muse_local.py validate                         # 校验完整种子库
```

也可以直接读文件:`seeds/index.json` 是全量索引,`seeds/<场景>/<种子>.md` 是完整种子。

1. **理解需求,不定方案。** 搜索前不要定死颜色、动效、布局、字体。只判断用户真正要什么(明示要求 + 隐含约束),以及哪些维度最关键。维度的答案来自种子,不来自想象。
2. **广搜。** 按场景 `list` 或跨场景 `search`(英文关键词,按问题搜而非按风格搜:"number density hierarchy" 而非 "minimal grid")。把候选摘要看完,不急于设计。
3. **定 wow,选维度。** 挑 1–3 个有意外强点的种子:一个大胆的布局决策、一个出人意料的配色、或一个偏执打磨的微交互,胜过三个安全平庸的参照。决定深读哪些维度。
4. **取深。** `show` 读完整种子:正文各维度即实现级细节;若文末有 `Dimensional References`(代码级参考),一并精读。seed 是全局锚点,维度细节是工艺——两者都要,只有梗概丢工艺,只有细节丢结构。
5. **锁 recipe。** 运行 `recipe` 生成 1–3 个种子的机器可读草案,完整填写参照角色、借用约束、单一焦点、释放区、色彩/字体/布局/图像/动效/工艺、实现要求、原创性改变与检查证据。详细契约见 [references/composition-recipe.md](references/composition-recipe.md)。有空字段就不要进入实现。
6. **实现并检查。** 让所有高能元素服务于一个 `focal_event`,同时保留一个明显更安静的 `release_zone`;按参照实现,再在真实尺寸和缩略视图检查。界面类产物同时检查关键状态、内容极值、响应式、键盘焦点与可访问性。

## 默认陷阱(必须避开)

以下是最廉价的模型默认值。真实参照不长这样,跟着参照走就能避开:

- **脏调色板**:蓝紫渐变、金融科技默认蓝、Tailwind 默认色、玻璃拟态 + 粉彩描边、装饰性彩虹渐变。
- **图标容器**:emoji、彩色圆角方块里的 Font Awesome。更好的做法:纯文字、手绘内联 SVG、或选对图像。
- **无意义动效**:图片悬停缩放/旋转、fade-in-up、hover scale-105、loading 转圈、没有理由的滚动触发显现、跑马灯。
- **卡片套卡片**:用留白、字重和分隔线代替层层嵌套。
- **描边 + 圆角 + 强调条**:组合装饰框、顶部/左侧色条、按钮下糊背景的阴影。
- **模板文案**:居中 hero + 两个 CTA + 三张等高特性卡、三档定价高亮中间档、悬浮客服挂件、"modern and elegant"、空洞的 "powerful"、执行摘要式 bullet、emoji bullet。
- **公式化字体**:把某个展示字体当作"优雅/科技"的默认信号。严格按参照的字重字号配对来。

## 工程硬规则

- **字体必须能渲染页面文字。** 页面含中文时,字体栈必须显式包含中文字体。不要用纯拉丁展示字体(Dela Gothic One、Bebas、Anton)渲染中文标题——中文会掉回系统默认字体,破坏整体感。拉丁/中文混排:`'LatinDisplay', 'ChineseFont', sans-serif`。系统字体栈(`-apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`)最安全;Google Fonts 中文字体必须 `font-display: swap`。
- **中文不用斜体。** 中文没有真斜体,`font-style: italic` 产生机械倾斜的伪斜体,损害可读性。中文强调用字重、颜色、背景高亮、字号、字距或换字体(楷/宋)。拉丁斜体需要时,用仅拉丁的 `@font-face` 限定范围。
- **图像:代码绘制或外链,有意识地选。** 图像主导的产物通常需要图像,但坏图像不如没有。选项:(1) 代码绘制(SVG/canvas/WebGL/CSS)——可控、无死链;(2) 外链(如 Unsplash,须验证 URL 存在)。都不合适就别放图,用排版/留白/色彩顶上。禁止:空白图像区、不搭的低质图、低精度代码画。

## 合成 —— 组合,不变异

产物从种子库借**具体约束**并组合,不是凭记忆变异。

**三条硬规则:**

1. **参照必须有单一角色。** 每个种子只负责已声明的维度;同一维度冲突时选一个答案,不做平均风格。先指定一个第一眼焦点和一个释放区,不要让所有元素平均用力。
2. **颜色必须来自参照。** 主色(背景、强调、文字)必须取自种子;不要自己发明。参照中没有的语义色(次级/状态/多系列/主题变体),从参照色板推导(同色温、同饱和度、同明度阶梯),并记录来源,不要另起炉灶。
3. **实现不得降级。** 参照怎么做就怎么做。不要为了省工把参照的技术、材质、结构或动效换成简化版。细节即价值,丢细节即丢质量。

**最低适配:** 用参照的方法装用户的内容。换成用户的文字、图像与场景;保留参照的布局、色彩、字体、动效与材质。既不照抄参照的内容,也不发明参照没有的技术。

**原创性防火墙:** 参照是视觉语法,不是模板。不得复制独特的对象排列、标题断行、标识、文案、边框系统、插画或签名;相对任何一个参照,至少主动改变四项结构变量(主体/裁切、网格、标题位置、字体配对、画幅、组件组织、动效或材质应用位置),并写入 recipe。

## 输出规则

- 不要把参照原文整段粘进最终答案。
- 不要向用户提及种子 id、检索参数或"基于某个参照"——把设计决策呈现为你对用户需求的综合判断。
- recipe 是内部决策与验收账本;除非用户要求过程细节,最终交付只呈现成品和必要的设计说明。
- 本库是固定的 29 个种子。**如果广搜后没有合适参照,换关键词再搜;仍没有,就明说"库中无匹配参照"**,然后基于上述陷阱清单与硬规则谨慎设计,不要强行套用差的匹配。
- 跨场景借用是允许的(如把 frontend 的动效思路用于社媒图文),但首先要用尽本场景的种子。
